# Design, build, and check

Read when the part needs a screen or interaction agreed, building, or proof. First confirm its scope and approval;
load the skills for this part's subject, not every skill.

## Design

**Done when** Jafar has approved an example, and its location and what stays undecided are saved.

Reuse approved examples. When the experience is unsettled, show the smallest useful mockup or prototype of the main
journey and its important states, on the devices it is for. Try a prototype when using something teaches more than
talking about it. The campaign works without any particular design tool.

An approval covers what was shown, not other screens or journeys. Save changed behaviour in its plan topic; a
change to the core needs Jafar's yes first. More detail can be designed part by part; an open visual choice blocks
only the work that depends on it.

## Build and check

**Done when** the agreed behaviour works, it has been checked in the way it deserves, and the proof is linked.

Before substantial building, follow `proven-development` and the project skills for this part's subject and risk,
and look at the existing code. Save the approach, the rules that must always hold, what happens on failure, and how
it will be checked, in the part note or a linked implementation plan. Choose technical details yourself.

Build one complete part, including the failure cases the agreed behaviour needs. Check the real journey against the
plan, and run the project checks that matter. Anything users see has its main journey tried in the live app;
documentation or skill work is tried in real use or with a fresh session instead. Small changes get small checks;
risky work gets the project's specialist checks. A prototype proves only the question it was built for.

Keep a short proof note: what was checked, where the evidence is, and what is still not proven. If checking raises
a new product question, research it and ask Jafar only that; carry on with work that does not depend on it. Before
finishing or handing over, read [handover.md](handover.md).
